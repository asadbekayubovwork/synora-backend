Qo'ng'iroqlar

Ovoz brauzer bilan agent o'rtasida to'g'ridan-to'g'ri oqadi (WebRTC, UDP). Backend faqat signallingni — offer va ICE candidate'larni — uzatadi va agent kalitini o'zida saqlaydi. Audio bizdan o'tmagani uchun server qo'ng'iroq qancha davom etganini heartbeatdan biladi: birinchisi media ulanganda, keyin sozlamadagi oraliqda. Hisob agent javob bergan paytdan tugatishgacha, server soatida.

Heartbeat timeout ichida kelmasa, server qo'ng'iroqni darhol yopmaydi — avval agentdan so'raydi. Agent uni hali ushlab turgan bo'lsa, hisob davom etadi; ushlamayotgan bo'lsa — oxirgi tiriklik dalili + bitta oraliqqacha, disputed belgisi bilan. Klient ham kutib o'tirmaydi: timeout davomida birorta heartbeat o'tmasa, qo'ng'iroqni o'zi yopadi (heartbeat_lost).

Hold — shift narxi: qo'ng'iroq ochilishida VOICE_AGENT_MAX_SESSION_SECONDS ga yetadigan kredit band qilinadi va ortig'i tugaganda qaytadi — chap paneldagi reserved. Birinchi heartbeatgacha yetmagan, ya'ni hech qachon ulanmagan qo'ng'iroq bepul: hold to'liq qaytadi. Mikrofonni o'chirish hisobni to'xtatmaydi.

Liniya peer connection bilan band: DELETE qilingan, lekin agentga hali ulangan qo'ng'iroq ham sanaladi, va keyingisi 429 voice_call_still_connected oladi — eski tab yopilguncha. Bunday qo'ng'iroq DELETE gacha hisoblanadi; undan keyingi ovoz hisobsiz — ma'lum cheklov, bitta liniya bilan chegaralangan.

Bitta tarmoq ichida STUN yetadi; turli tarmoqlar orasida (mobil internet, korporativ NAT) TURN kerak — VOICE_AGENT_TURN_URLS va VOICE_AGENT_TURN_SECRET (har foydalanuvchiga muddatli credential, Sozlama kartasida muddati) yoki VOICE_AGENT_ICE_SERVERS. TURN bo'lmasa media ulanmaydi, qo'ng'iroq 20 s dan keyin connection_failed bilan tugaydi va hech narsa yechilmaydi.
Bu raqamlar bizning usage_events jadvalimizdan, upstreamdan emas. events har bir metrika bo'yicha alohida sanaladi — bir chaqiruv ikki metrika yozsa, umumiy son ikki bo'ladi (app/schemas/tts.py:907).
Bitta sintez uchta satr qoldiradi: hold → release → debit, hammasi bitta group_id ostida.
